# LLMGate design notes (milestone 2)

Milestone 1 left `ChatPipeline` as the seam in front of the adapters, and left a Redis client on `GatewayState` that no feature used. This milestone uses both. The HTTP route still authenticates, starts the stream, and writes the access line. It does not decide whether to retry.

## Why the route stays thin

A retry that lived in the OpenAI adapter would not run for Anthropic, and a retry that lived in the route would have to know which errors are safe to repeat. The pipeline already resolves a public model to a provider. It now also calls that provider. Retries, fallback, and the circuit breaker wrap that call. Adding a provider is still a new adapter plus a registry entry.

The response body stays OpenAI-shaped. A gateway quota rejection is `429` with `error.type = rate_limit_error`. An upstream failure that exhausts retries and fallbacks stays `502` or `504`. A bad gateway key stays `401`. Upstream authentication failures stay `502`, for the same reason as milestone 1: a `401` means the caller's gateway key is wrong.

## What is safe to repeat

Only transient failures are retried: connection errors, timeouts, an upstream `429`, and upstream `5xx` mapped to `ProviderError`. A `400` or `404` is a property of this request. Sending it again, or to a different provider, will not make it valid.

A missing provider credential is not retried. Repeating a call with a blank API key cannot succeed. It can fall through to the next candidate, because a different provider may be configured.

Backoff is full jitter: `random.uniform(0, min(cap, base * 2^attempt))`. The default is 3 attempts, a 0.2s base, and a 2s cap. Tests pass the sleep function in, so they count delays without waiting.

A stream is retried only before the first chunk is yielded. After that the HTTP status is already committed. A later failure still becomes an SSE error object followed by `data: [DONE]`, which is the milestone 1 rule.

Each failed attempt counts toward the circuit breaker. A later success on that provider clears the streak. A missing credential does not count: it is configuration, not an outage.

## Why fallback is a list, not a guess

Each registry entry may name later public model ids. `gpt-4o-mini` falls back to `claude-3-5-haiku`, then `gemini-2.0-flash`. A `provider/model` prefix has no fallback. The caller named that provider on purpose.

Automatic "try any other provider" would spend a different model's quota and can reject tools. Tool calls only fall back to `openai`, because the other adapters already reject `tools`. A cycle in the fallback list stops at the first repeated id.

The response `model` field stays the id the caller sent. Clients keep parsing one name. The access line's `model` and `provider` are the candidate that served the request, or the last one tried. `retry.scheduled`, `provider.fallback`, and `circuit.open` are separate log events. They do not include prompts or keys.

## Why both controls live in Redis

The breaker is per provider, shared by every gateway process. Five consecutive transient failures open it for 30 seconds. While that window is active the provider is skipped and the pipeline tries the next candidate. The open flag and the half-open probe are timestamps in Redis, compared with the recovery window. One `SET NX` allows a single probe after the window. Success deletes the failure count, the open flag, and the probe. A crashed probe cannot block the provider past the recovery window, and tests can move the clock without waiting on Redis TTL.

The token bucket is per gateway key. The default holds 60 tokens and refills one per second. It runs after authentication and before any provider call. An upstream `429` is that provider's limit: it is retried, then it may fall back. The gateway's own `429` is the caller's quota: it is not retried, and `Retry-After` is the number of seconds until one token is available. The read-modify-write sits behind a short `SET NX PX` lock. The commands are `GET`, `SET`, `INCR`, and `DEL`, not `EVAL`, so the same code runs on Redis and on the `FakeAsyncRedis` the tests already use.

If Redis cannot run the bucket, the request fails closed with `503` and `code = rate_limiter_unavailable`. A gateway that cannot enforce quota must not spend provider money. If Redis cannot read the breaker, the call proceeds and a warning is logged. The breaker is an optimization. The quota check is a safety control. `GET /healthz` still reports Redis down.

## What this milestone still does not do

No semantic cache, no budgets, no PII redaction, no dashboard. Those stay later milestones. The breaker does not shed load inside a single process beyond skipping an open provider, and the bucket counts requests, not tokens generated by the model.
